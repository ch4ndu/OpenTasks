# OpenTasks Full Audit — 2026-07-16

Scope: entire project (379 Kotlin files, ~39.4k lines) including uncommitted working-tree changes.
Method: seven scoped audit passes (data, sync, domain+DI, ViewModels, non-calendar UI, calendar UI, platform) against `docs/ai/audit.md`, `ui.md`, `data-sync-time.md`, `widgets.md`, `architecture.md`, plus mechanical grep checks and correctness/performance review. Severity: critical > high > medium > low. Confidence: confirmed / likely / possible.

## High severity

**[STALE_SNAPSHOT_OVERWRITE]** high/confirmed - `data/sync/BaseSyncAdapter.kt:159-178` (also `AttachmentSyncAdapter.kt:95-124`)
Pull merge snapshots local rows once (`getAllOnce()`), compares each remote record against the stale snapshot, and upserts unconditionally with `isSynced = true`. A local edit committed while the merge loop runs can be overwritten by an older remote row and is never pushed — permanent silent data loss. Window spans the whole merge loop (seconds for attachments with downloads).
Fix: conditional upsert (`ON CONFLICT DO UPDATE ... WHERE excluded.updatedAt > <table>.updatedAt`) or per-row re-read + compare inside a transaction.
Failure: snapshot has task X at T1; remote has T2>T1; user saves T3>T2 mid-merge; loop upserts remote (T2>T1) with isSynced=true → T3 edit gone locally, never pushed.

**[CORRECTNESS]** high/confirmed - `ui/screens/DateReminderSheet.kt:123, 188-207, 287-298`
Duration-tab recurrence never propagated: confirm branch (selectedTab==1) propagates day/time/end/all-day/reminders but never calls `onRecurrenceSelected(durRecurrence)`; `durRecurrence` is also not seeded from `selectedRecurrence` when opening on the Duration tab.
Fix: call `onRecurrenceSelected(durRecurrence)` in the tab-1 branch; initialize from parent state.
Failure: user sets Repeat=Weekly on the Duration tab, confirms, saves → task saved with no recurrence; editing a recurring duration task shows Repeat=None.

**[DATE_MATH]** high/confirmed - `data/calendar/IcsParser.kt:174-181`
All-day ICS dates pinned to UTC midnight (`atStartOfDayIn(TimeZone.UTC)`), then `utcToLocal()` applied at import → in negative-UTC-offset timezones the task lands on the previous local day. Mirror bug on export (`IcsGenerator.kt:54-55, 89-100`, medium/likely) for UTC+9:30 and above.
Fix: treat all-day values as civil dates — use `TimeZone.currentSystemDefault()` in both all-day branches.

**[CORRECTNESS]** high/confirmed - `androidApp/.../widget/CalendarWidgetContent.kt:45-57`, `WeekWidgetContent.kt:44-56` vs `MainActivity.kt:48`, `App.kt:219-226`
Widget day cells send `widget_action="view_calendar"` + `calendar_year/month/day` extras; MainActivity extracts only `widget_action`, App.kt handles only `create_task`/`view_list` → tapped date silently dropped.
Fix: read the extras in MainActivity, pass into `App()`, add a `view_calendar` branch navigating to the Calendar tab at that date. (Pairs with the in-progress calendar-navigation work.)

**[RECOMPOSITION]** high/confirmed - `ui/screens/calendar/CalendarScreen.kt:417-421` (UNCOMMITTED)
New chevron-enable logic reads `collapseProgress.value` (Animatable — changes every frame of the 350ms collapse animation) and `activePagerState.isScrollInProgress`/`canScrollBackward`/`canScrollForward` in the `CalendarContent` body → the entire calendar screen recomposes per animation frame and at every swipe start/end. Regression introduced by the working-tree diff.
Fix: `remember(currentView) { derivedStateOf { ... } }` for the three booleans, or compute enablement inside `CalendarPeriodNavigation`.

**[CORRECTNESS]** high/confirmed - `viewmodel/TaskListViewModel.kt:230-243` (+ dead flows `:149-167`)
`renameSection()`/`deleteSection()` read `activeTasksForSelectedCategory.value`, which has no collectors — with `WhileSubscribed(5000)` it is permanently `emptyList()`, so both methods silently no-op. No UI callers exist either: the feature is dead and broken. Three superseded projection pipelines duplicate `listProjection` logic.
Fix: delete the methods and the three dead flows, or read via `listProjection`/a UseCase inside the Action.

## Medium severity

### Sync

**[SYNCNOW_EARLY_RETURN]** medium/confirmed - `data/sync/SyncService.kt:39-47` + `domain/action/settings/TriggerSyncAction.kt:60-68`
`syncNow()` returns immediately when `tryLock` fails (sets `pendingSyncRequested`) though documented as suspending until completion. Pull-to-refresh spinner ends instantly; that pass's errors go to the other caller.
Fix: suspend on the mutex / await in-flight + pending pass.

**[PENDING_SYNC_LOST_WAKEUP]** medium/likely - `data/sync/SyncService.kt:44-65`
Flag set after the do-while condition evaluates but before unlock → requested pass never runs until the next unrelated trigger; rows stay unsynced.
Fix: re-check `pendingSyncRequested` after unlock (loop around the lock) or use a conflated Channel.

**[ORPHAN_PUSH_STARVATION]** medium/likely - `BaseSyncAdapter.kt:166-171,206-207` + `TaskTagSyncAdapter.kt:109-120` + `SyncService.kt:111-118`
One permanently orphaned server `task_tags` row → degraded on every pass → task_tags push skipped forever on all devices; tag assignments never sync. `validateRemoteRecord` doesn't exempt remote tombstones.
Fix: silently skip orphan remote tombstones; allow push after merged-with-skips pulls (rule targets failed pulls).

**[CASCADE_DROPS_SYNCED_CHILDREN]** medium/possible - `BaseSyncAdapter.kt:98-101` + `data/model/TaskTag.kt:15-27` (FK CASCADE)
Hard-delete of a never-synced task tombstone cascades task_tags rows that may have synced (task push failure does not skip task_tags push) → orphaned server row forever (feeds the starvation above).
Fix: hard-delete only never-synced children; keep/push tombstones for children with a `pbId`.

**[ATTACH_RETRY_OVERRIDES_LWW]** medium/possible - `AttachmentSyncAdapter.kt:174-182`
`localFileMissing`/`retryRemoteDownload` overrides apply an older remote over newer local state; `isRemoteOriginDownloadFailure` ignores `local.isDeleted` → an unsynced attachment tombstone is resurrected as synced-active (delete lost).
Fix: `!local.isDeleted` guard on the override; merge only file fields on override-driven re-download.

**[NEW_SERVER_ADOPTION_IMPOSSIBLE]** medium/likely - `SavePocketBaseUrlAction.kt:23` + `BaseSyncAdapter.kt:187-191`
Fresh zero-row server → zero-row degraded exception → URL save aborts. No supported way to migrate existing data to a new server (Clear Local Data destroys the data being migrated).
Fix: first-connect/migration mode, or persist the URL and surface degraded state.

**[PERF_ATTACH_REDOWNLOAD]** medium/likely - `AttachmentSyncAdapter.kt:105-123`
Any newer remote metadata change (e.g. sortOrder) re-downloads the full file even when `record.file` matches local `remoteFileName` and the file exists.
Fix: skip the download when name matches and file present; merge metadata only.

### Data / date-time

**[RECURRENCE_DRIFT]** medium/confirmed - `data/extensions/DateTimeUtils.kt:157-230` (`computeNextDeadlineUtc/Local`)
MONTHLY/YEARLY advancement re-anchors on the clamped previous occurrence → permanent day-of-month drift: Jan 31 → Feb 28 → Mar 28 forever; Feb 29 yearly → Feb 28 forever. Affects task recurrence and countdown projection (`CountdownOccurrence.kt:97-104`).
Fix: anchor to the original occurrence's day-of-month; occurrence N = anchor + N×interval months with per-occurrence clamping.

**[DISTINCT_UNTIL_CHANGED]** medium/confirmed - `data/repository/AppSettingsRepositoryImpl.kt:19-20`
`observeValue()` is the only repository read flow missing `distinctUntilChanged()`; any `app_settings` write re-emits every observed key → ViewModel churn.
Fix: append the operator.
