## Implementation design and ownership

### Shared recovery

Add a conservative pass-owned operation-policy boolean defaulting to false in
SyncPassContext/SyncPassContextFactory. Only SyncService.syncPass explicitly enables
normal-sync equal-divergence recovery. Initial account activation pulls, standalone
adapter calls, and both seed modes never enable it. Gate Base and Attachment pull and
push retry paths with that flag; seed wrappers also suppress recovery even if handed
an enabled pass. Initial pulls retain current strictly-newer remote merge and pristine
Inbox adoption behavior, and fail closed on unresolved equal divergence. This prevents
an initial activation from promoting old local contents into newly selected-account
writes. No account-flow refactor is needed.

Modify `BaseSyncAdapter.kt` and the seven existing adapters. Add a small pure
entity-copy hook that preserves all local content, deletion state, creation time,
relations, and local-only fields. No entity-to-record round trip for recovery.
Use the existing pass-owned Room writer transaction to reread the current row,
prove the equal timestamp and divergent canonical payload, and upsert the copied
row with `updatedAt = maxOf(utcNow(), previousUpdatedAt + 1)` and `isSynced = false`.
Reject Long.MAX_VALUE overflow. Adopt only the validated owner-scoped remote ID.
Prefer this existing transaction seam over new per-DAO queries or schema changes.
A stale captured row may not overwrite a newer local edit or a row that disappeared.

Perform equal-divergence detection before a DAO merge can overwrite a pristine
Inbox placeholder. Equal canonical matches retain the existing placeholder identity
adoption; actual content divergence follows the new user-selected local-wins rule.
Missing-parent and invalid-identity validation still runs before conflict recovery.

For push-time conflicts, return or throw a specific validated-conflict result carrying
the required remote identity/timestamp. The normal push wrapper rereads/rebases under
the writer transaction, rebuilds the complete request, and retries from a fresh server
preflight once. No retries for unrelated errors and no unbounded retry loop. Persisted
rebase survives interruption; failed uploads leave it pending. Preserve conditional
mark-synced checks so stale responses cannot acknowledge a newer local edit.

Both normal and authoritative seed paths remain excluded from automatic rebasing.
Do not use `allowRemoteMerge` alone to identify normal sync: non-authoritative seed
also uses true. Preserve seed inventory validation and authoritative conflict behavior.

### Attachment boundary

`AttachmentSyncAdapter.kt` uses the same recovery contract at its specialized pull,
active multipart, and tombstone conflict branches. Validate owner/type/kind/parent
identity first. Preserve its canonical comparison subset, which excludes server file
names and platform-derived media details. Preserve local paths and attachment bytes.
Never promote a download placeholder, blocked row, or missing-file row to a successful
upload; retain its existing file safety semantics and surface inability to recover.
Only upload-eligible local records become pending upload. Both seed modes stay excluded.

Close the remaining tombstone acknowledgement gap: raw validation before decoding,
exact direct/preflight/update target IDs, complete localId/timestamp/canonical metadata,
isDeleted=true, and blank server file before confirmation or cleanup. A malformed 2xx
create remains ambiguous and uses existing owner-localId recovery. Preserve `file-`
removal, cleanup leases, and retained paths; no file protocol redesign.

If active upload bytes are missing, retain the row and files and report collection
failure instead of returning apparent success. Preserve the specific missing-file
reason when recording failure. A parent without a remote ID remains existing deferral.

### Acknowledgement persistence

In Base, propagate identity-save and mark-synced DAO errors after safe logging;
never return Pushed following a failed remote-ID save. Zero-row conditional acknowledgement
caused by a concurrent change remains the existing safe stale-response behavior.
